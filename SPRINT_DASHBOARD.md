# Sprint-End Merge Visibility Dashboard

**Purpose**: Show what's being deployed, test results, coverage changes, and version info at each merge to main.

This dashboard is generated automatically by GitHub Actions at each merge and stored as an artifact.

## Dashboard Components

### 1. **Merge Summary** (What changed?)
- Commit SHA, author, timestamp
- Affected packages
- Test coverage changes (+/- %)
- New dependencies

### 2. **Test Status** (Did everything pass?)
- Overall pass rate
- Per-package results
- Coverage metrics
- Integration test status

### 3. **Deployment Readiness** (Is it safe to deploy?)
- ✅ All CI checks passed
- ✅ Coverage meets threshold (80%+)
- ✅ No security issues
- ✅ Backward compatible
- ✅ Temporal compatibility verified

### 4. **What's Being Deployed**
- Version info from `.tool-versions`
- Go version
- Temporal SDK version
- Dependencies

### 5. **Quality Metrics**
- Test count: 59 tests
- Pass rate: 100% (all passing)
- Coverage: 64.4% overall → target 80%
- Performance: <1s local, ~2 min CI

## How to Access

### During PR (Check Merge Readiness)
1. Open PR
2. Scroll to "Checks" section
3. Click "Sprint Summary Report" artifact
4. Download and review

### After Merge (What Was Deployed)
1. Go to Actions
2. Find the workflow run
3. Download "sprint-summary-report" artifact
4. Share with team via Slack/email

## Branch Protection Configuration

Before merging to main, verify:

1. ✅ All required checks pass:
   - verify-versions
   - test-local (1.21, 1.22)
   - test-coverage (≥64%)
   - test-bridge
   - test-events
   - test-integration
   - build

2. ✅ Coverage requirements:
   - Overall: 64.4%+ (working toward 80%)
   - Events: 98.6%+
   - Bridge: trending upward

3. ✅ Commit requirements:
   - Descriptive message
   - No breaking changes documented
   - Tests included

4. ✅ Review requirements:
   - At least 1 approval (for main branch)
   - Conversations resolved
   - No requested changes

## Automation

The sprint summary is generated by:
1. `verify-versions` — Checks `.tool-versions` consistency
2. `sprint-summary` job — Generates full report
3. Artifact storage — 30 days retention for audit trail

To view:
```bash
# Local test (simulates dashboard)
make test
make test-coverage

# View latest CI report
gh workflow-run list | head -5
gh run view <RUN_ID> --log
```

To add custom metrics:
1. Edit `.github/workflows/test.yml` → `sprint-summary` job
2. Add new sections to report template
3. Commit and test on next merge

## Integration with Slack/Teams

Can be extended to post reports automatically:
```yaml
- name: Post to Slack
  uses: slackapi/slack-github-action@v1
  with:
    payload: ${{ env.SPRINT_REPORT }}
```

(Configure in future sprints as needed)
